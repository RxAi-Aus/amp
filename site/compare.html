RxAi AMP compared with Mem0, Zep, Letta and the MCP memory server RxAi AMP 與 Mem0、Zep、Letta、MCP 記憶伺服器的比較

All five give an AI agent memory that outlasts a session. They differ in where that memory lives, how it reaches the agent, and what you have to run. This page compares how each is designed, as its own documentation describes it on 24 September 2026. It does not rank them; each fits a different job.

這五種方案都讓 AI 代理擁有跨工作階段的記憶。差別在於記憶存在哪裡、怎麼送到代理手上，以及你得維運什麼。本頁依各專案自己的文件（2026 年 9 月 24 日查證）比較它們的設計，不排名次：它們各自適合不同的工作。

IN SHORT

The one-line difference一句話的差別

RxAi AMP
Memories are GitHub Issues in a repository you own. Hooks give each agent the ones that match its task, and outcome comments reweight what agents trust. No database or server.記憶是你自己倉庫裡的 GitHub Issue。Hook 把和任務相符的記憶交給每個代理，成效留言調整代理信任哪些記憶。不需要資料庫或伺服器。
Mem0
A memory layer your code calls: it stores memories in a vector store and your app searches them. Open source, or the hosted Mem0 Platform.由你的程式呼叫的記憶層：記憶存在向量資料庫，由你的應用程式搜尋。可用開源版，或託管的 Mem0 Platform。
Zep / Graphiti
A temporal knowledge graph. Graphiti is the open-source framework and needs a graph database; Zep is the hosted service.具時間性的知識圖譜。Graphiti 是開源框架，需要圖資料庫；Zep 是託管服務。
Letta
An agent framework, formerly MemGPT, in which the agent edits its own memory through tool calls. Runs on Postgres, or as Letta Cloud.代理框架（前身為 MemGPT），代理透過工具呼叫編輯自己的記憶。執行於 Postgres，或使用 Letta Cloud。
MCP memory serverMCP 記憶伺服器
The reference knowledge graph from the Model Context Protocol project, kept in one local JSONL file and used through MCP tools.Model Context Protocol 專案的參考實作：知識圖譜存在一個本機 JSONL 檔，透過 MCP 工具使用。

Changed recently: Zep stopped maintaining its self-hosted Community Edition in April 2025, and its open-source work continues as Graphiti. Mem0’s graph memory moved to the hosted platform. Letta’s docs now recommend git-backed memory repositories over shared memory blocks.

近期變動：Zep 於 2025 年 4 月停止維護可自架的 Community Edition，開源工作改由 Graphiti 延續。Mem0 的圖記憶移到託管平台。Letta 的文件現在建議改用以 git 為基礎的記憶倉庫，而不是共享記憶區塊。

WHEN TO CHOOSE

Which one fits哪一個適合你

  • RxAi AMPSeveral coding agents, and the people working with them, share the same repositories. You want every memory reviewable as a GitHub issue with its history, and you would rather not run a database.多個程式代理和與它們合作的人共用同一批倉庫。你希望每條記憶都能以 GitHub Issue 審閱並保有歷史，而且不想維運資料庫。
  • Mem0 · ZepAn application needs semantic search over a large amount of user or conversation memory, and you are fine running a vector or graph store, or paying for a hosted one.應用程式需要對大量使用者或對話記憶做語意搜尋，而且你願意維運向量或圖資料庫，或付費使用託管服務。
  • LettaYou are building the agent itself and want memory management to be part of the framework it runs in.你在打造代理本身，希望記憶管理是它所用框架的一部分。
  • MCP memory serverMCP 記憶伺服器One person wants a small local knowledge graph inside an MCP client, with nothing else to set up.一個人想在 MCP 用戶端裡用一個小型本機知識圖譜，其他什麼都不想設定。

What AMP does not try to do: its recall matches memories by title and place, not by embeddings, so semantic search across thousands of memories is not its goal. It needs GitHub. How much it saves depends on the model; the benchmarks show where it pays for itself and where it does not.

AMP 不打算做的事：它的召回靠標題與 Place 比對記憶，而不是向量嵌入，所以對上千條記憶做語意搜尋不是它的目標。它需要 GitHub。能省多少取決於模型；基準測試列出它在哪裡划算、在哪裡不划算。
