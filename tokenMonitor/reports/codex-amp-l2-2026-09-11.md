and `SessionEnd` hooks in 20 fresh, ephemeral, read-only sessions: five
AMP-on/off pairs for each model at medium reasoning.

Negative percentages mean the L2 AMP-on arm used less than its disabled pair.
All 20 cases exited successfully. The 10 AMP-on ledgers were all closed at
`SessionEnd`, each recorded three injected issues from the target project's
Region (`#355`, `#373`,
`#368`), and no AMP-off ledger was created. The models were not required to
cite an injected memory, so explicit memory citations were 0/4 for both.

## Method

- Same four investigation tasks on the target project, and the same expected
  issues, as the L1
  benchmark; 20 sessions total, five counterbalanced pairs per model.
- AMP-on ran with the installed hook runtime and a temporary isolated
  `CODEX_HOME`; AMP-off used the same hooks with `AMP_DISABLE=1`.
- Hook trust was bypassed only for this non-interactive, pre-vetted test home;
  the normal installation was trusted interactively before the run.
- User connectors were excluded from the isolated home, while the configured
  AMP clone and GitHub issue transport supplied the injected bodies.
- Usage comes directly from Codex `turn.completed` events. `cached_input_tokens`
  is a subset of `input_tokens`; uncached input is their difference.

Raw JSONL, answers, ledgers, `summary.json`, and `report.md` were retained in
the local gitignored benchmark output directory during the run.
