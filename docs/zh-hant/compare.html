RxAi AMP 與 Mem0、Zep、Letta、MCP 記憶伺服器的比較

這五種方案都讓 AI 代理擁有跨工作階段的記憶。差別在於記憶存在哪裡、怎麼送到代理手上，以及你得維運什麼。本頁依各專案自己的文件（2026 年 9 月 24 日查證）比較它們的設計，不排名次：它們各自適合不同的工作。

IN SHORT

一句話的差別

RxAi AMP
記憶是你自己倉庫裡的 GitHub Issue。Hook 把和任務相符的記憶交給每個代理，成效留言調整代理信任哪些記憶。不需要資料庫或伺服器。
Mem0
由你的程式呼叫的記憶層：記憶存在向量資料庫，由你的應用程式搜尋。可用開源版，或託管的 Mem0 Platform。
Zep / Graphiti
具時間性的知識圖譜。Graphiti 是開源框架，需要圖資料庫；Zep 是託管服務。
Letta
代理框架（前身為 MemGPT），代理透過工具呼叫編輯自己的記憶。執行於 Postgres，或使用 Letta Cloud。
MCP 記憶伺服器
Model Context Protocol 專案的參考實作：知識圖譜存在一個本機 JSONL 檔，透過 MCP 工具使用。

WHEN TO CHOOSE

哪一個適合你

  • RxAi AMP多個程式代理和與它們合作的人共用同一批倉庫。你希望每條記憶都能以 GitHub Issue 審閱並保有歷史，而且不想維運資料庫。
  • Mem0 · Zep應用程式需要對大量使用者或對話記憶做語意搜尋，而且你願意維運向量或圖資料庫，或付費使用託管服務。
  • Letta你在打造代理本身，希望記憶管理是它所用框架的一部分。
  • MCP 記憶伺服器一個人想在 MCP 用戶端裡用一個小型本機知識圖譜，其他什麼都不想設定。

AMP 不打算做的事：它的召回靠標題與 Place 比對記憶，而不是向量嵌入，所以對上千條記憶做語意搜尋不是它的目標。它需要 GitHub。能省多少取決於模型；基準測試列出它在哪裡划算、在哪裡不划算。
