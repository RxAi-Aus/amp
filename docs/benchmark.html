RxAi AMP · Benchmarks

Does memory pay for itself? 記憶真的划算嗎？

We test it the way you would test a new study trick. Two identical AI helpers get the same homework. One of them also gets a sticky note from the shared memory. Then we count every word each of them reads and writes. This page explains how it works, simply enough for a ten-year-old and precisely enough to run it again yourself.

測試方法就像測試一個新的讀書技巧：兩個一模一樣的 AI 助手拿到同一份作業，其中一個另外拿到一張來自共享記憶的便利貼。然後，我們把兩個助手讀進和寫出的每一個字都算清楚。這一頁說明它怎麼運作：簡單到十歲小孩也看得懂，精確到你可以自己重跑一次。

THE TEST

Twin helpers, one sticky note 雙胞胎助手，一張便利貼

Each test is a pair of brand-new sessions with the same AI model. They are identical in every way except one: whether the AMP hooks may hand the helper the memories that match its task.

每一次測試都是一對全新的工作階段，使用同一個 AI 模型。兩者只差一件事：AMP 的 hook 是否可以把跟這份作業相關的記憶交給助手。

AMP ON

Helper A助手 A

  • same model and effort level
  • same tools, read-only
  • + a sticky note: the hooks inject the matching memories

  • 同一個模型、同一個思考強度
  • 同一組工具，唯讀
  • ＋ 一張便利貼：hook 注入相關的記憶

  • same model and effort level
  • same tools, read-only

Keeping it fair 怎麼保持公平

01 · ONE SWITCH

Only one thing differs只有一個差別

Prompt, model, tool allowlist and project are identical. The only difference between the two helpers is the memory switch.

提示、模型、工具白名單、專案都一樣。兩個助手之間唯一的差別，就是記憶開關。

AMP_DISABLE=1
02 · TAKE TURNS

They take turns going first輪流先跑

In one pair the memory helper runs first, in the next pair the other one does. Neither side always gets the warm start of a filled prompt cache.

這一對由有記憶的助手先跑，下一對換另一個先跑。這樣沒有任何一方總是佔到「快取已經熱好」的便宜。

(pair + model) % 2
03 · REPEAT

Do it many times重複很多次

One try could just be luck, so tasks rotate across pairs and every question is asked more than once.

只試一次可能只是運氣，所以題目在不同的配對之間輪替，每一題都會問不只一次。

--cases 16 → 8 pairs
04 · TRICK QUESTION

One question has no answer in memory有一題是陷阱題

The control task is one no memory covers. It checks that memory stays quiet, and costs nothing, when it has nothing useful to say.

對照題是沒有任何記憶涵蓋的題目。它檢查記憶在幫不上忙的時候，會不會乖乖保持安靜、不多花成本。

"expectedIssue": null
05 · FROZEN MEMORY

The memory box is frozen記憶盒子是凍結的

Memories keep changing weight as the store compiles. The helpers read a pinned copy with its remote removed, so every run sees the same records.

記憶的權重會隨著每次編譯改變。助手讀的是一份固定的副本，並移除了遠端，所以每一輪看到的記憶都一樣。

--memory-repo <snapshot>
06 · HANDS OFF

Look, don't touch只能看，不能動

Sessions may read files and run read-only commands, nothing else. Personal connectors are switched off, so AMP is the only memory under test.

工作階段只能讀檔、執行唯讀指令，其他一律不行。個人的外部連接器全部關閉，所以受測的記憶只有 AMP。

--strict-mcp-config
RECEIPTS

How the tokens are counted token 是怎麼算的

A token is a small piece of a word. The helper is charged for every token it reads and every token it writes.

token 是一小段字。助手讀進的每一個 token、寫出的每一個 token，都要付費。

It doesn't do the homework in one go. It works in steps: think, open a file, think again, open another file. Each step is one call to the model, and at every call it re-reads the whole conversation from the beginning, like reading your whole notebook again before you write the next sentence. That is why the reading count grows so fast.

它不會一口氣寫完作業，而是一步一步來：想一想、打開一個檔案、再想一想、再打開另一個檔案。每一步都是對模型的一次呼叫，而且每一次呼叫，它都會把整段對話從頭再讀一遍，就像每寫下一句話之前，都要把整本筆記從頭讀一次。這就是為什麼「讀的量」長得那麼快。

call 1第 1 次
call 2第 2 次
call 3第 3 次
call 4第 4 次
call 5第 5 次
bookmarked: re-read from cache, about a tenth of the price書籤：從快取重讀，大約一成的價格 new: read for the first time, full price新內容：第一次讀，全價 written: output, private thinking included寫出：輸出，包含內部思考

An illustration, not measured data. Call 1 holds the system prompt, the question and (for helper A) the sticky note. Each later call carries everything before it plus the file it just opened. Add up every bar and you get the context tokens.

這是示意圖，不是實測數據。第 1 次呼叫裝著系統提示、題目，以及（助手 A 才有的）便利貼。之後每一次呼叫，都帶著前面所有內容，再加上剛打開的檔案。把所有長條加起來，就是「context token 總量」。

The receipt printed after every call 每次呼叫之後印出的收據

The runner starts Claude Code with --output-format stream-json, which prints one line per model call with a usage block. The benchmark adds the fields up across the whole session.

執行器用 --output-format stream-json 啟動 Claude Code，每次模型呼叫都會印出一行，內含一個 usage 區塊。benchmark 把整個工作階段的這些欄位加總起來。

GRADING

Checking the homework 批改作業

Being cheaper means nothing if the answer is wrong. Every answer gets three checks: one on its content, one on what the model says it used, and one on what the hooks actually delivered.

答案如果錯了，再便宜也沒有意義。每個答案都要經過三道檢查：一道看內容，一道看模型說自己用了什麼，一道看 hook 實際送出了什麼。

CHECK 1 · KEYWORDS

Did it name the right things?有沒有講到對的東西？

Each task lists signals: file and function names a correct answer should mention. The runner checks which ones appear. This is a deterministic check, not a quality grade.

每一題都列出「訊號」：正確答案應該提到的檔名和函式名稱。執行器檢查哪些有出現。這是固定規則的比對，不是品質評分。

"signals": [ … ]
CHECK 2 · RECALL LINE

Did it say which note helped?它有說是哪張便利貼幫了忙嗎？

Every answer must end with a line naming the memories it used. Right means the expected memory is named, or none on the trick question.

每個答案結尾都必須有一行，列出它用到的記憶。答對的意思是：列出了預期的那則記憶；陷阱題則要回答 none。

Recall used: #N | none
CHECK 3 · LEDGER

Was the note really handed over?便利貼真的交出去了嗎？

The hooks keep a diary of what they injected and how much of it: the title only, or a short summary. The runner copies it next to each result.

hook 會寫一本日誌，記下它注入了什麼、注入了多少：只有標題，還是一段簡短摘要。執行器把這本日誌複製到每筆結果旁邊。

ledger · pointer | summary

Checks 2 and 3 are kept apart on purpose. In one September 2026 run, two sessions had the right summary in front of them and still wrote Recall used: none. A single "memory hits" number would have called that a retrieval miss; the ledger shows the memory was delivered and simply not credited.

第 2 和第 3 道檢查刻意分開。2026 年 9 月的一次測試中，有兩個工作階段明明看到了正確的摘要，卻還是寫了 Recall used: none。如果只有一個「記憶命中」數字，會被誤判成沒有取到記憶；日誌則證明記憶確實送到了，只是沒有被標註出來。

SCORE

Keeping score 計分方式

change = (AMP on − AMP off) ÷ AMP off × 100%

Each measurement is summed over every successful session in each arm. A negative number means the memory helper used less. "Cheaper pairs" counts how often the memory helper beat its own twin.

每一項數字都是把該組所有成功的工作階段加總。負數代表有記憶的助手用得比較少。「比較便宜的配對」計算有記憶的助手贏過自己雙胞胎的次數。

In kid terms: with the sticky note, the helper read less overall, dug up less, and finished a bit faster. But the note itself is new, full-price text, so the total bill came out about the same, slightly higher on average. Both helpers got the homework equally right.

用小朋友的話說：有了便利貼，助手整體讀得比較少、挖得比較少，也稍微快一點寫完。但便利貼本身是新的、全價的文字，所以總帳單差不多，平均還稍微高一點。兩個助手的作業正確度一樣好。

What the benchmark taught us 這個 benchmark 教會我們的事

The two "after" rows should agree and don't quite: with only two pairs per task, one control session that dug up 8 KB more and one cold-cache first session are enough to move cost by ten points. Read the direction — memory reads less and costs a little more — not the decimals.

兩列「之後」照理應該一致，卻有落差：每題只有兩對時，一個多挖了 8 KB 的對照題工作階段，加上一個快取還沒熱的第一個工作階段，就足以讓成本差十個百分點。請看方向——記憶讓它讀得少、成本略高——不要看小數點。

The first sticky note listed a person's decisions one by one. The helper treated the list as homework of its own and went to check every item, so memory made it read more. The fix was to hand over only a short goal-and-status summary, and only for tasks the memory matches; the full record stays one fetch away. Same model, same questions: reading flipped from +28% to −14%.

第一版的便利貼把某人的決定一條一條列出來。助手把這張清單當成自己的作業，逐項去檢查，結果記憶反而讓它讀得更多。修正方法是只交出一段簡短的「目標加現況」摘要，而且只在題目和記憶相關時才給；完整紀錄需要時再去取。同一個模型、同樣的題目：閱讀量從 +28% 翻轉為 −14%。

An earlier run with Opus 5 produced the numbers on the overview page: 18% less dug up from files, 5% cheaper, 14% faster. A model that reads little to begin with gained nothing there. Memory saves blind exploration, so the more a model explores, the more memory pays.

總覽頁上的數字來自更早一輪的 Opus 5 測試：從檔案挖出的量少 18%、成本低 5%、快 14%。本來就讀得少的模型，在那一輪沒有得到好處。記憶省下的是「盲目探索」，所以模型越愛探索，記憶越划算。

Same test, different receipts 同一個測試，不同的收據

Codex runs the same experiment with the same task table and schedule. Its receipts come from the turn.completed event at the end of each turn:

Codex 跑的是同一個實驗，用同一張題目表與排程。它的收據來自每一回合結束時的 turn.completed 事件：

cached_input_tokensThe bookmarked part of that; uncached = input − cached其中有書籤的部分；未快取 = input − cached

  • Codex never prints a price, so cost is worked out from a price list (config/prices.json): uncached input × input price + cached input × cached price + output × output price. On a ChatGPT plan nothing is billed per token; the number is what the same traffic would cost on the API.
  • Isolation: --ignore-rules and --disable memories switch off Codex's own saved approvals and its built-in memory, so AMP is the only memory being tested.
  • Per-call detail: with --rollouts the runner also reads each session's rollout file for per-call numbers: calls per case, the first call's size, the biggest call, and cold starts.
  • By hand vs by hook: when four Codex models had to fetch memory themselves (load the skill, read the index, search), they read 39–80% more and took 31–52% longer for 0–2 useful hits in 4 tasks. When the hooks delivered the same records, the change ranged from −5.6% to +36%. That result is why every runtime that can run hooks must use them (PROTOCOL.md §15.3).
  • Codex 從來不印價格，所以成本是用價目表（config/prices.json）算出來的：未快取輸入 × 輸入單價 ＋ 快取輸入 × 快取單價 ＋ 輸出 × 輸出單價。ChatGPT 方案不是按 token 計費；這個數字代表同樣的流量在 API 上要花多少錢。
  • 隔離：--ignore-rules 和 --disable memories 關掉 Codex 自己存下的核准規則與內建記憶，讓受測的記憶只有 AMP。
  • 逐次呼叫的細節：加上 --rollouts 時，執行器還會讀每個工作階段的 rollout 檔，取得逐次呼叫的數字：每題的呼叫次數、第一次呼叫的大小、最大的一次呼叫，以及冷啟動次數。
  • 手動 vs hook：四個 Codex 模型自己去找記憶時（載入 skill、讀索引、搜尋），4 題只得到 0–2 次有用命中，卻多讀 39–80%、多花 31–52% 的時間。由 hook 送上同樣的紀錄時，變化落在 −5.6% 到 +36%。這就是為什麼所有能跑 hook 的執行環境都必須使用 hook（PROTOCOL.md §15.3）。

LIMITS

What it can't tell you 它無法告訴你的事

  • Small samples. A run is usually 8 pairs per model. One unusual session can move a percentage by several points.
  • Keywords are not a grade. The checklist confirms the right names appear, not that the explanation is good.
  • Cost is a list-price estimate. Claude Code reports it; for Codex it is computed from the price list.
  • Compare like with like. Only compare runs made on the same pinned memory snapshot and the same prompt wording; each report prints its Prompt rules: vN.
  • No fixed seed. There is no temperature or seed to pin. The paired, turn-taking design is what absorbs the randomness.
  • 樣本小。一輪通常是每個模型 8 對。只要一個工作階段比較特別，百分比就可能差好幾個點。
  • 關鍵字不等於評分。檢查清單只確認對的名稱有出現，不代表解釋得好。
  • 成本是牌價估計。Claude Code 會自己回報；Codex 的則是用價目表算出來的。
  • 要比較同類的結果。只比較使用同一份固定記憶快照、同一版提示措辭的測試；每份報告都會印出 Prompt rules: vN。
  • 沒有固定種子。沒有 temperature 或 seed 可以固定，靠的是「成對、輪流先跑」的設計來吸收隨機性。
