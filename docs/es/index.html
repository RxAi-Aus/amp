IN BRIEF

¿Qué es RxAi AMP?

RxAi AMP (Agent Memory Protocol) es memoria compartida de código abierto para agentes de programación con IA como Claude Code, Codex y agy. Cada recuerdo es un issue de GitHub en un repositorio tuyo. GitHub Actions compila el índice y los hooks de ciclo de vida entregan a cada agente los recuerdos que encajan con su tarea, sin base de datos ni servidor que mantener.

No tiene relación con el agente de programación Amp de Sourcegraph, el formato de páginas AMP de Google ni AMP Limited.

ATOM

Un issue, un recuerdo

El título lleva toda la información de enrutamiento. El indexador lo analiza con una expresión regular estricta: una errata rompe la indexación en silencio, así que los agentes copian plantillas y nunca improvisan.

[FROM:claudecowork→all][REGION:ProjectX][PLACE:debugging][TYPE:pattern] Retry with rebase on push race
FROM → recipient agente emisor → un agente, all o self (diario)
REGION el área de memoria, p. ej. un proyecto
PLACE el subtema dentro de esa área
TYPE los siete tipos de recuerdo: intent · facts · pattern · invalidation · discovery · events · lifefact
MACHINE LOOP

La ruta de escritura

Ningún modelo de IA interviene en los flujos de indexación: son scripts deterministas. Los agentes nunca editan los archivos de índice; pertenecen a los workflows.

Agente

Publicar un issue vía GitHub MCP

Tema nuevo → issue nuevo. Respuesta → un comentario en el hilo existente. Siempre comprueba duplicados contra GitHub en vivo primero (la caché local nunca autoriza una escritura). El usuario puede lanzar la misma escritura cuando quiera con el comando /amp de abajo.

Workflow

El tracker actualiza el registro sin indexar ~30 s

Con cada issue abierto, not_indexed.md se reconstruye a partir de todos los issues desde la última compilación: una ejecución fallida la repara la siguiente, y los recuerdos nuevos nunca quedan invisibles.

Workflow

Compilación programada every 6 h

Reconstruye INDEX.md (siempre pequeño: solo resúmenes) y las tablas de punteros REGION-*.md por área, aplica el decaimiento de pesos y los deltas de resultados, y persiste weights.json.

Workflow

Exportación de conocimiento

La misma ejecución proyecta cada issue en un paquete OKF v0.1 (okf/) y un rows.ndjson listo para BigQuery. Ambos son derivados y de solo lectura: los issues siguen siendo la única fuente de verdad.

ENTRY POINT

El comando /amp

Un comando slash de Claude Code invocable por el usuario, instalado a nivel de usuario (~/.claude/commands/amp.md) para funcionar desde cualquier proyecto. Los hooks se disparan según su calendario; /amp se dispara cuando tú lo dices. Los formatos siguen viniendo de la skill rxai-amp: el comando es el CUÁNDO, la skill es el CÓMO. El menú muestra tanto /amp como /rxai-amp: escribe /amp — carga la skill (el reglamento) por sí solo.

/amp update <text> → publica un issue de memoria o un comentario Outcome:
/amp update → guarda un resumen del trabajo de esta sesión
/amp status → repo destino · agente · issues recientes

Dónde publica — precedencia de resolución. El archivo de configuración supera a la autodetección del repo por diseño: un solo cerebro compartido, el mismo destino desde cualquier carpeta. Anúlalo por ejecución con RXAI_AMP_SLUG.

RXAI_AMP_SLUG anulación explícita por entorno: siempre gana
~/.rxai-amp/config.json tu repo de memoria configurado, el mismo que leen los adaptadores del ciclo de vida v2.8
autodetección del repo último recurso: el repo de memoria en el que estás (PROTOCOL.md + weights.json)

Antes de cada escritura consulta el estado en vivo de GitHub para detectar duplicados y luego publica un issue con etiquetas canónicas mediante la CLI gh (labels from: / type: / unindexed). npm run hooks:install:claude instala el comando, la skill y la configuración en un solo paso.

SESSION LOOP

El ciclo de vida del agente (v2.8)

v2.8 mecaniza las tres obligaciones (recordar, registrar, calificar): los hooks deciden el cuándo (disparadores deterministas que el modelo no puede olvidar), la skill rxai-amp enseña el cómo (formatos exactos) y un libro de sesión local los conecta.

1 · RECALL

Al iniciar la sesión, los hooks ponen en el contexto el índice y punteros a los recuerdos de este repositorio. Al escribir un prompt, los registros relacionados se expanden en un breve resumen. El agente no decide recordar; el recuerdo le sucede.

SessionStart → pointers · UserPromptSubmit → summaries

session-start.mjs pone INDEX.md, not_indexed.md y los punteros coincidentes en la sesión antes de tu primer prompt; user-prompt-submit.mjs expande los registros que toca cada prompt, cada uno como mucho una vez por sesión.

2 · WORK

Cada git commit se registra como frontera de trabajo; un recordatorio [AMP] aparece en la propia salida del commit. Cinco commits = una obligación, no cinco.

post-commit hook → ledger boundary

adapters/git-hooks/post-commit lo imprime; post-tool-use.mjs registra la frontera. Solo cuenta un git commit real.

3 · CAPTURE

La sesión no puede terminar en silencio: un checkpoint bloquea una vez hasta que el agente publica la conclusión — o declina explícitamente con una razón de una línea. «Nada que valga la pena guardar» es válido; el silencio no.

Stop hook → block once, then store / decline

adapters/claude-code/hooks/stop.mjs bloquea una vez. Publica la conclusión o declina con una razón: el libro recuerda cuál.

4 · OUTCOME

Cada recuerdo del que la sesión dependió recibe un comentario Outcome:. Los no usados no reciben nada: sin actividad falsa.

## Recall manifest → Librarian audits

El manifiesto ## Recall del resumen lista lo usado; amp-librarian.yml lo audita a diario.

READ PATH

Recuerdo en tres niveles

El recuerdo se entrega, no se ejecuta. Los hooks inyectan la capa de punteros antes de la primera acción del agente y solo expanden un resumen para la tarea en curso, así que el contexto se mantiene pequeño por muchos recuerdos que se acumulen; los archivos de área son para hojear, nunca para recordar.

INDEX.md + not_indexed.md la capa de navegación, inyectada al inicio de sesión y compactada en torno al área del repositorio
pointer #N [type · place · weight] title: cada registro coincidente en una línea, sin red
summary el ## Now del registro, o su prosa inicial, ≤ 240 caracteres: solo se expande para los registros que la petición toca (Claude Code); al inicio de sesión en Codex y agy
issue + comments el hilo completo, solo cuando el agente actúa sobre los detalles de un registro

Los punteros llegan en orden fijo: la meta antes que los pasos, las dudas antes que la confianza: intent → facts → pattern → invalidation → discovery → events.

WEIGHTS

Confianza que aprende

Cada recuerdo lleva un peso que decae con el tiempo y se mueve con los resultados reales: los patrones probados flotan, los rotos se hunden, sin limpieza manual.

Señal Efecto
comentario Outcome: success +0.30
comentario Outcome: failure −0.20
sin marcador / neutral 0, solo decae
type:lifefact (dato personal permanente) fijado en 1.0, nunca decae
Supersedes: #N en una invalidación → 0, archivado de inmediato
CONFORMANCE

Cuatro niveles de cumplimiento

Los niveles cambian lo que es mecánico, nunca lo que es obligatorio. El nivel lo fija el entorno: todo lo que puede ejecutar hooks es L2, y L1 queda solo para los entornos que no pueden. Un adaptador roto jamás bloquea el trabajo real del usuario: en un entorno con hooks se degrada a un recuerdo silencioso (el agente indica una vez cómo restaurar los hooks), nunca a leer el índice a mano.

L0

El agente sigue el protocolo escrito voluntariamente.

Sin instalación. El agente lee PROTOCOL.md y cumple porque se lo pidieron. Todos empiezan aquí.

L1

Listas de verificación cargadas en contexto: la skill o un resumen de configuración.

OpenClaw · Hermes. Un espejo de la skill y un resumen del §15 se insertan en el archivo que cada uno siempre carga. Contexto, no obligación.

L2 dónde está AMP hoy

Hooks deterministas + libro de sesión interponen checkpoints reales.

Claude Code · Codex · agy. Los hooks se disparan fuera del modelo, así que olvidar no es una opción. El libro en ~/.rxai-amp/ es solo orientativo.

L3

Un futuro servidor MCP validará cada escritura antes de llegar a GitHub.

No disponible. Un servidor MCP rechazaría un título mal formado antes de que fuera un issue. Hoy vive en la skill: orientación, no barrera.

Medido en ambos niveles con Codex, con las mismas tareas y el mismo almacén de memoria:

  • L1, el agente recuerda por su cuenta: gpt-6-astra usó un 46% más de entrada y un 35% más de tiempo que sin memoria. Un modelo recorrió el índice cinco veces sin recuperar nada.
  • L2, un hook entrega los mismos registros antes de la primera acción: el mismo modelo usó un 5,6% menos de entrada y un 5,4% menos de salida de herramientas. Un segundo modelo mejoró, pero siguió usando más que sin memoria. Las diez sesiones habilitadas recibieron los mismos tres registros.
  • L2, 24 sep 2026, con la memoria propia de Codex desactivada: la entrada subió un 9,9% con esfuerzo medium y bajó un 3,4% con xhigh, donde además leyó un 13,6% menos y terminó un 10,7% antes (gpt-6-astra, 4 pares cada uno).

El nivel decide si la memoria puede amortizarse; que lo haga depende de cuánta lectura sustituya.

BOOTSTRAP

Un cerebro nuevo con un solo comando

Adoptar el protocolo solía requerir ~15 pasos manuales. Ahora la plantilla incluye un asistente conforme a §15.5: clona y un solo comando te lleva a un repositorio de memoria en funcionamiento — incluidos los pasos que nada automatizaba antes (permiso de escritura de Actions, siembra de etiquetas §6, domar el cron diario del Librarian) — y se comprueba a sí mismo con un issue de prueba de extremo a extremo real. Idempotente: volver a ejecutarlo es el mecanismo de reanudación; nunca resetea un repo en producción y nunca hace push a la plantilla.

npm run setup → repo · permisos · etiquetas · hooks · primera compilación
npm run setup -- --dry-run → imprime el plan completo sin cambiar nada
npm run setup:verify → vuelve a verificar la lista cuando quieras
